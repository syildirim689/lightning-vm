# Türkçe / İngilizce desteği

## Seçim: next-intl
`next-intl` 4.x seçildi:
- Next.js App Router ve Server Component'lerle doğrudan çalışır.
- ICU mesaj biçimini (değişken, çoğul) ve `Intl` tabanlı tarih/sayı/para biçimlendirmeyi tek API'de sunar.
- Mesaj anahtarları TypeScript ile tiplenir; olmayan bir anahtar build'i bozar.

URL öneki (`/tr/...`) kullanılmıyor: panel arama motoruna açık değil ve dil kullanıcı tercihidir.
Kurulum: https://next-intl.dev/docs/getting-started/app-router/without-i18n-routing

## Dil nasıl belirlenir
1. `NEXT_LOCALE` cookie'si geçerliyse (`tr` veya `en`) o kullanılır.
2. Yoksa tarayıcının `Accept-Language` başlığı q-değerine göre sıralanır; ilk desteklenen dil seçilir.
3. Hiçbiri desteklenmiyorsa İngilizce.

Kenar çubuğundaki dil düğmeleri bir Server Action ile cookie'yi 1 yıllığına yazar
(`SameSite=Lax`). Sayfa sunucuda yeni dille yeniden çizilir; JavaScript kapalıyken de çalışır.
Cookie yalnızca dil tercihi taşır. `Secure` bayrağı HTTPS aşamasında (5. aşama) eklenecek.

Saat dilimi kullanıcıya göredir: hesapta seçilen dilim (`users.time_zone`), seçilmemişse tarayıcının dilimi.
`components/time-zone-sync.tsx` bunu `lvm-tz` çerezine yazar, `i18n/request.ts` tarihleri bu dilimle çizer.
Çerez yoksa veya geçersizse sunucu genelindeki `APP_TIME_ZONE` kullanılır (varsayılan `UTC`).

## Dosyalar
- `apps/web/messages/tr.json`, `en.json`: tüm kullanıcı metinleri.
- `apps/web/i18n/config.ts`: desteklenen diller ve `Accept-Language` seçimi.
- `apps/web/i18n/request.ts`: istek başına dil, saat dilimi ve mesajlar.
- `apps/web/i18n/actions.ts`: dil değiştirme.
- `apps/web/global.d.ts`: mesaj anahtarlarının tiplenmesi.

## Hata kodları
API her hatada `{ code, message }` döndürür:
- `code` sabit, İngilizce bir anahtardır (`DEPENDENCY_UNAVAILABLE`, `NOT_FOUND` …).
- `message` geliştiriciler içindir ve arayüzde gösterilmez.

Arayüz `errors.<code>` çevirisini gösterir. Çevirisi olmayan bir kod gelirse `errors.UNKNOWN`
gösterilir. Ağ hatası (`NETWORK`), API hatasından ayrı gösterilir.

Teknik loglar kararlı İngilizce olay kodları kullanır (`redis_unavailable`, `unhandled_error`).
Bunlar çevrilmez.

## Eksik çeviri kontrolleri
- `apps/web` içinde `npm test` (`apps/web/scripts/check-messages.mjs`) şunları kontrol eder:
  - her dilde aynı anahtarların bulunması;
  - boş metin olmaması;
  - aynı `{değişken}` adlarının kullanılması;
  - API kaynağındaki her `code: '...'` için `errors.*` çevirisinin bulunması.
- `npm run build`: kodda kullanılan ama `en.json`'da olmayan anahtar TypeScript hatasıdır.
- `npm run test:e2e` (Playwright, çalışan bir Compose kurulumuna karşı): tarayıcı diline göre
  ilk dil, dil değiştirme ve kalıcılığı, API hata kodu ve alan hatası çevirisi, ağ hatası ayrımı.
  Sayfalarda konsol hatası olmadığı da kontrol edilir.

## Yeni metin eklemek
1. Anahtarı önce `en.json`'a, sonra `tr.json`'a ekleyin.
2. Bileşende `useTranslations('Bölüm')` (Server Component'te async ise `getTranslations`) kullanın.
3. `npm test && npm run build` çalıştırın.

## Saat dilimi
Her kişi Hesap → Profil → Bölge'den kendi saat dilimini seçer (boş: tarayıcınınki). Seçim `users.time_zone`
alanında tutulur; `TimeZoneSync` bileşeni bunu `lvm-tz` çerezine yazar ve `i18n/request.ts` sunucuda tüm
tarihleri bu dilimde biçimlendirir. İstatistiklerdeki günler ve saatler de aynı dilime göre hesaplanır.
